02 · Base conceptualDe hardware físico a máquina virtual

La virtualización permite compartir el hardware de un servidor físico entre varios sistemas operativos aislados, mediante una capa de software llamada hypervisor que reparte CPU, memoria, red y disco entre las máquinas virtuales.

Al servidor físico se lo llama host; a cada máquina virtual, guest.

03 · Modelo de nubeIaaS: infraestructura como servicio

El modelo IaaS (Infrastructure as a Service) consiste en que el proveedor cloud entrega la infraestructura virtualizada (máquinas virtuales, almacenamiento y red) como un servicio bajo demanda. El cliente conserva la responsabilidad del sistema operativo, el middleware, las aplicaciones y los datos.

La facturación se realiza por consumo real, medido por segundo u hora, sin inversión inicial en hardware ni compromisos de largo plazo obligatorios.

Modelos de servicio en la nube

IaaS — Máquinas virtuales, discos, redes.
Ejemplos: EC2, GCE, Azure VMs, OCI Compute.

PaaS — Plataforma de ejecución administrada.
Ejemplos: App Engine, Elastic Beanstalk.

SaaS — Aplicación lista para el usuario final.
Ejemplos: Gmail, Salesforce.

04 · PanoramaLos cuatro proveedores del mercado

Los cuatro proveedores concentran el 70 % del mercado global de IaaS. Comparten el mismo núcleo funcional; las diferencias reales están en costo, ecosistema y capa gratuita.

05 · Modelos de preciosPago por uso vs. instancias reservadas

Pago por uso (On-Demand)

Se factura por segundo o por hora, sin compromiso previo. Ideal para pruebas, picos o cargas impredecibles.

Ejemplo: t3.micro en AWS us-east-1 = USD 0,0104/h (~USD 7,59/mes 24/7).

Instancias reservadas / Committed Use

Compromiso de 1 o 3 años a cambio de descuentos que van del 37% al 72%. Se paga menos por hora pero hay que asegurar el consumo.

Modalidades: sin pago inicial, pago parcial o pago total por adelantado (la más barata).

También existen las Spot Instances (AWS) y Preemptible VMs (GCP): descuentos de hasta el 90% a cambio de que el proveedor pueda apagar la VM con pocos minutos de aviso. Sirven para procesamiento batch tolerante a fallos.

08 · Análisis comparativoFortalezas y debilidades · AWS y GCP

AWS EC2

Fortalezas

+ 34 regiones y 108 zonas de disponibilidad (líder mundial).
+ Más de 200 servicios integrados en el mismo ecosistema.
+ Documentación exhaustiva y comunidad activa.
+ Certificaciones profesionales muy valoradas en el mercado laboral.
+ Descuentos Spot de hasta el 90% para cargas tolerantes a fallos.

Debilidades

– Consola con curva de aprendizaje pronunciada.
– Costos ocultos en tráfico saliente (~USD 0,09/GB).
– Free tier expira a los 12 meses (cuentas viejas) o se agota el crédito.
– Facturación difícil de predecir sin herramientas adicionales.

GOOGLE COMPUTE ENGINE

Fortalezas

+ Descuentos automáticos por uso sostenido (hasta 30%) sin contratar nada.
+ Red interna de fibra propia, latencia baja entre regiones.
+ Instancia e2-micro gratis sin vencimiento.
+ Facturación por segundo desde el primer minuto.
+ Interfaz más limpia que AWS.

Debilidades

– Menos regiones (~40) que AWS y Azure.
– Catálogo de servicios más reducido.
– El free tier solo aplica en 3 regiones específicas.
– Soporte en español limitado.

08 · Análisis comparativoFortalezas y debilidades · Azure y Oracle

AZURE VIRTUAL MACHINES

Fortalezas

+ Integración nativa con Active Directory y Windows Server.
+ Programa Azure for Students: USD 100 sin tarjeta de crédito.
+ Licencias híbridas con descuentos si ya se pagan on-premise.
+ 60+ regiones, la mayor cobertura geográfica.
+ Soporte empresarial fuerte en Argentina y LATAM.

Debilidades

– Portal ocasionalmente lento y con cambios frecuentes de UI.
– Free tier corto (12 meses) y USD 200 solo válidos 30 días.
– Nomenclatura de series (B, D, E, F...) confusa para principiantes.
– Precios equivalentes o superiores a AWS en la mayoría de instancias.

ORACLE CLOUD INFRASTRUCTURE

Fortalezas

+ Free tier más generoso del mercado, sin vencimiento.
+ 10 TB mensuales de egress incluidos (AWS cobra ~USD 900 por lo mismo).
+ Precios competitivos en cargas empresariales y bases Oracle.
+ Autonomous Database gratuita hasta 20 GB.
+ Buena performance en instancias ARM Ampere.

Debilidades

– Menos servicios que AWS, GCP y Azure.
– Escasez de capacidad ARM en varias regiones (a veces no deja crear la VM).
– Documentación menos madura, ejemplos más escasos.
– Reclama capacidad si la instancia queda inactiva mucho tiempo.

Elegimos Oracle Cloud Always Free porque no expira. El procedimiento es equivalente en AWS y GCP; cambian los nombres del panel y las reglas de firewall.

09.1 · Caso prácticoConfigurar la VM y desplegar la web

Con la instancia Ubuntu 22.04 creada, la IP pública asignada y el puerto 80 abierto en la Security List, nos conectamos por SSH:

# Conexión SSH desde nuestra máquina local
ssh -i clave_privada.key ubuntu@<IP_PUBLICA>

# Actualizar el sistema e instalar Nginx
sudo apt update && sudo apt upgrade -y
sudo apt install nginx -y

# Abrir el puerto 80 en el firewall interno de Ubuntu
sudo iptables -I INPUT 6 -m state --state NEW -p tcp --dport 80 -j ACCEPT
sudo netfilter-persistent save

# Reemplazar la página por defecto por nuestra web
sudo nano /var/www/html/index.html

# Verificar que Nginx esté corriendo
sudo systemctl status nginx

Abrimos el navegador con la IP pública y ya tenemos la web sirviendo. Tiempo total: menos de 15 minutos.

10 · Cosas a tener en cuentaPros y contras del caso práctico

Ventajas

  • Cero costo si se respeta el free tier.
  • Ambiente reproducible: se puede clonar la VM o usarla como plantilla.
  • La VM se apaga y se prende cuando se necesita, sin perder configuración.
  • Se puede escalar vertical (más CPU/RAM) u horizontal (más VMs) sin cambiar el código.
  • Excelente para practicar Linux, redes y despliegue de aplicaciones reales.

Limitaciones

  • El free tier tiene cupos: si nos pasamos empieza a cobrar automáticamente.
  • El tráfico saliente (egress) suele ser lo que más se paga fuera del compute.
  • Requiere tarjeta de crédito para verificar la cuenta (menos en Azure for Students).
  • La VM Ampere A1 usa arquitectura ARM: algunas apps no tienen binarios nativos.
  • El proveedor puede reclamar capacidad si la VM está inactiva mucho tiempo (Oracle).

11 · ConclusionesQué nos llevamos

  • El modelo IaaS convirtió al servidor en un objeto virtual, replicable y trasladable. Ya casi ningún proyecto nace en un servidor físico propio.
  • Los cuatro proveedores son técnicamente equivalentes para levantar una web. La diferencia real está en costo, ecosistema y free tier.
  • Para un estudiante o proyecto personal, la mejor combinación es Oracle Cloud (Always Free) como servidor principal y GCP e2-micro como respaldo.
  • Para empresas medianas o grandes, la elección depende del ecosistema ya adoptado: si usan Microsoft 365 y AD, Azure encaja; si necesitan la mayor variedad de servicios, AWS sigue liderando.
  • Levantar un servidor web en la nube deja de ser un tema de fierros y pasa a ser un tema de configuración, seguridad y monitoreo.
